# Competitor Screenshot Hub｜最终执行版 PRD

- 日期：2026-05-19
- 项目名：`competitor-screenshot-hub`
- 项目性质：新建独立项目 / 独立 GitHub 仓库
- 托管方式：GitHub Pages 公开托管
- 当前版本：执行前收敛版

## 1. 一句话定位

一个公开可体验的竞品截图知识库网站：用户可以在线查阅已有竞品截图、按流程/标签搜索，也可以提交采集需求；已支持的 APP/通用流程由本地执行器自动采集，遇到高风险节点暂停并说明原因，新 APP/新流程进入兜底工单。

## 2. 背景

目前已经沉淀了多轮消费金融竞品 APP 截图、逐图台账、流程证据图和页面分析。领导希望把现有能力工具化，让其他同学不只是看一次性报告，而是可以通过公开网站自行查阅竞品页面证据，并提交新的采集需求。

本项目不是旧 `AI-Competitor-Radar-v2` 的升级。旧项目仅作为 GitHub Pages 托管方式参考，本次新建独立项目。

## 3. 产品目标

### 3.1 MVP 要做到

1. 公开访问：通过 GitHub Pages 打开即可体验。
2. 截图查阅：展示已有竞品截图资产。
3. 筛选搜索：按竞品、流程、业务模块、标签、关键词搜索。
4. 流程浏览：按业务流程串联截图，而不是只看单张图片。
5. 采集入口：用户可以提交“想采集哪个 APP / 哪个流程 / 哪个页面”。
6. 任务状态：用户可以看到采集进度、已采集节点、暂停原因和结果链接。
7. 过程展示：边采集、边上传、边展示过程；正式入库前保留复核/脱敏机制。
8. 本地回流：本地执行器采集后把截图和 metadata 回流到网站项目。

### 3.2 MVP 不做

1. 不做完整 AI 自动分析报告平台。
2. 不做复杂登录/权限系统。
3. 不让公网用户直接实时控制欧文电脑或手机。
4. 不自动执行身份证、人脸、银行卡、签约、授信提交、借款提交、支付/提现/还款/转账等高风险动作。
5. 不承诺所有需求即时完成；新 APP/新流程需要配置。
6. 不做纯云端 APP 自动采集；纯线上化作为远期方向。

## 4. 目标用户

| 用户 | 核心需求 |
|---|---|
| 产品/业务同学 | 快速查某个竞品页面、某条流程、某类业务触点 |
| 管理者 | 快速看到竞品关键页面证据和流程样例 |
| 欧文/维护者 | 维护截图库、处理采集任务、把结果回流网站 |

## 6. 第一版页面结构

### 6.1 首页 `/`

目标：让用户快速理解工具能力。

内容：

- 项目介绍。
- 已收录竞品数、截图数、流程数。
- 快捷入口：截图库、流程库、搜索、提交采集需求、任务状态。
- 最近更新。
- 风格：工具站为主，首页保留展示感。

### 6.2 截图库 `/library`

目标：集中浏览所有截图。

能力：

- 截图卡片展示。
- 表格视图，可选。
- 按竞品筛选。
- 按流程筛选。
- 按业务模块筛选：APP、风控、客服、消金、留存促活运营。
- 按标签筛选。
- 按时间版本筛选。
- 区分已采集 / 待补采 / 未复核 / 已脱敏。

### 6.3 流程库 `/flows`

目标：按业务流程串联截图。

第一版流程分类：

- 授信/查看额度。
- 客服/消保。
- 借款申请上游。
- 还款只读入口。
- 运营活动。

流程详情展示：

- 流程说明。
- 节点顺序。
- 节点对应截图。
- 已采集 / 待补采 / 等待人工接管状态。
- 相关竞品对比。
- 流程证据图，可选。

### 6.4 搜索页 `/search`

目标：让用户用关键词快速找截图。

第一版做前端本地搜索。

可搜索字段：

- 竞品名。
- 流程名。
- 页面节点。
- 页面说明。
- 可见关键文案。
- 标签。
- 业务模块。

示例搜索：

- “度小满额度页”
- “客服入口”
- “协议授权”
- “消费者保护”
- “小赢借款页”

### 6.5 截图详情页 `/screenshots/[id]`

目标：解释这张图是什么、来自哪里、属于哪个流程。

字段：

- 原图。
- 竞品。
- 流程。
- 页面节点。
- 页面说明。
- 可见关键文案。
- 标签。
- 截图时间 / 版本。
- 上一节点 / 下一节点。
- 来源文件名。
- 敏感信息状态：未检查 / 已检查 / 已脱敏 / 不可公开。

### 6.6 采集需求页 `/request`

目标：用户提交想采集的内容。

字段：

- 想采集的 APP。
- 想采集的流程。
- 想采集的页面或问题。
- 背景说明。
- 期望用途。
- 联系方式，可选。
- 优先级，可选。

提交后按支持情况分流：

| 判断结果 | 处理方式 |
|---|---|
| 已支持 APP + 已支持通用流程 | 进入采集队列 |
| 已支持 APP + 新流程 | 进入新流程探索任务 |
| 新 APP | 进入新 APP 接入工单 |
| 涉及高风险节点 | 标记为等待人工确认/接管 |
| 暂不支持 | 转工单或提示暂不支持 |

### 6.7 任务状态页 `/tasks`

目标：展示采集进度。

状态枚举：

| 状态 | 含义 |
|---|---|
| 已收到 | 系统已收到需求 |
| 排队中 | 等待本地执行器处理 |
| 执行中 | 本地设备正在采集 |
| 等待人工接管 | 涉及高风险节点或需要人工操作 |
| 已完成 | 已采集流程完成，结果可查看 |
| 复核入库完成 | 已进入正式截图库和搜索结果 |
| 暂不支持 | 当前 APP/流程尚未接入 |
| 失败 | 执行失败，等待复核 |

展示字段：

- 任务标题。
- 竞品。
- 流程/页面。
- 当前状态。
- 已采集节点。
- 暂停/失败原因。
- 更新时间。
- 结果链接。

正式截图库和搜索结果只收录经过复核、脱敏、节点确认后的截图。

需要区分：

- 采集完成：流程已经采到可采节点。
- 复核入库完成：截图已确认可作为正式资产展示和搜索。

### 8.1 已安装 8 个 APP

### 8.2 可自动采集的通用低风险流程

第一版采集目标是通用、低风险、可观察的页面流程，不是深度完成授信/借款。

可自动采集：

- APP 启动页/首页。
- 底部 Tab 切换：首页、借钱/借款、服务/客服、消息、我的等。
- 客服入口、帮助中心、常见问题、投诉反馈、消费者保护入口。
- 借钱/查看额度的上游入口页，但不提交真实申请。
- 运营活动页、弹窗、卡券/权益页。
- 我的页面、设置页、账号安全/隐私权限入口的只读页面。
- 公告、协议入口页、费率说明入口页等通用信息展示页。

### 8.3 必须暂停/停止的节点

一旦流程进入以下节点，本地执行器必须停止自动操作，并在任务页记录终止原因：

- 借款提交 / 确认借款 / 立即借款。
- 授信提交 / 申请额度 / 确认授权提交。
- 身份证填写、证件上传、证件拍照。
- 人脸识别。
- 银行卡绑定。
- 协议签署或勾选后提交。
- 支付、提现、还款、转账等资金动作。
- 验证码、短信码、支付密码、人脸活体等认证动作。

任务页终止说明示例：

```text
任务状态：等待人工接管
已采集节点：首页 -> 借钱入口 -> 查看额度说明页
终止原因：页面进入身份证填写/授信申请节点，属于高风险节点，自动采集已暂停。
后续建议：如需继续采集，由维护者人工接管并进行脱敏复核。
```

## 9. 采集任务闭环

### 9.1 任务分流规则

| 类型 | 判断条件 | 处理方式 |
|---|---|---|
| 已支持 APP + 已支持通用流程 | APP 已安装/登录/配置，流程路径已存在 | 进入采集队列，本地执行器执行 |
| 已支持 APP + 新流程 | APP 已配置，但流程未沉淀 | 生成新流程探索任务，人工跑一次后沉淀 |
| 新 APP | APP 未安装/未登录/未配置 | 生成新 APP 接入工单 |
| 高风险节点 | 涉及身份证、人脸、银行卡、签约、授信/借款提交等 | 必须暂停并等待人工接管 |
| 异常情况 | 登录失效、验证码、页面改版、脚本失败等 | 标记失败或转工单 |

### 9.2 用户侧流程

1. 用户在网站提交采集需求。
2. 系统判断属于哪类任务。
3. 可直接采集的任务进入队列。
4. 用户在任务状态页查看过程。
5. 采集完成后，用户通过结果链接查看已采节点。

### 9.3 本地执行侧流程

1. 本地执行器定期拉取任务。
2. 判断任务是否在支持范围内。
3. 低风险路径自动执行。
4. 高风险节点暂停并等待人工接管。
5. 每采到一张图，上传并回写节点状态。
6. 采集到可采终点后，标记采集完成。
7. 后续复核/脱敏。
8. 合格截图进入正式截图库和搜索结果。

## 10. 技术架构

### 10.1 总体方案

采用已确认组合：

> GitHub Pages 前台 + Cloudflare Worker/D1 任务 API + 本地执行器轮询 + GitHub Issue 兜底。

### 10.2 模块分工

| 模块 | 职责 |
|---|---|
| GitHub Pages 前台 | 展示截图库、流程库、搜索、采集入口、任务状态 |
| 静态数据仓库 | 保存截图、metadata、流程、标签、支持能力清单 |
| Cloudflare Worker | 接收采集需求、提供任务 API |
| Cloudflare D1 | 存储任务、节点状态、过程记录 |
| 本地执行器 | 拉取任务、控制本地电脑/手机采集、生成结果 |
| GitHub Issue 兜底 | 承接新 APP、新流程、异常失败、暂不支持任务 |

### 10.3 API 草案

| API | 用途 |
|---|---|
| `POST /api/tasks` | 用户提交采集任务 |
| `GET /api/tasks` | 任务状态列表 |
| `GET /api/tasks/:id` | 任务详情和过程节点 |
| `POST /api/tasks/:id/events` | 本地执行器回写采集进度 |
| `POST /api/tasks/:id/complete` | 本地执行器标记采集完成 |
| `POST /api/tasks/:id/fallback-issue` | 不支持任务转 GitHub Issue |

### 10.4 图片上传策略

第一版推荐：

1. 本地执行器截图落盘。
2. 本地执行器把截图提交到 GitHub 仓库：`public/screenshots/tasks/<taskId>/`。
3. 回写任务 API，记录图片路径和节点状态。
4. GitHub Pages 更新后，任务页展示图片。

后续如需更实时，再考虑 Cloudflare R2 对象存储。

### 10.5 推荐技术栈

- 前端：Vite + React 或 Next.js 静态导出。
- 样式：Tailwind CSS。
- 托管：GitHub Pages。
- 数据：JSON 静态文件。
- 搜索：Fuse.js / MiniSearch。
- 任务 API：Cloudflare Worker + D1。
- 本地执行器：Node.js 脚本 + ADB/Appium/本地 OpenClaw 能力。

## 12. 脱敏与安全规则

### 12.1 脱敏含义

脱敏不是“不展示”，而是对截图中不适合公开暴露的个人/账号/交易信息进行遮挡、替换或标记。

### 12.2 脱敏对象

| 信息类型 | 处理规则 |
|---|---|
| 姓名 | 遮挡或替换为 `**` |
| 手机号 | 只保留前 3 后 4，或全部遮挡 |
| 身份证号 | 全部遮挡 |
| 银行卡号 | 只保留后 4 位，或全部遮挡 |
| 人脸/证件照片 | 默认遮挡，不公开原始图 |
| 详细住址/单位 | 遮挡 |
| 合同号/订单号/协议编号 | 遮挡 |
| 验证码/短信码 | 不公开 |
| 真实借款申请、提交结果、合同页 | 默认不公开，除非人工判断可脱敏展示 |
| 额度/利率 | 通用页面展示可保留；个人真实授信结果标记敏感，按需要遮挡或仅展示字段结构 |

### 12.3 公开网站免责声明

建议首页或页脚增加：

> 本站内容仅用于竞品页面研究和流程观察，截图可能不是实时页面，不构成业务、金融或合规建议。涉及个人信息或敏感业务节点的截图会进行脱敏或不公开展示。

## 17. 远期思考：纯线上化

纯线上化可以作为远期方向，但不纳入 MVP。

真正的云端 APP 自动采集需要云手机/真机池、账号登录、风控处理、验证码处理和敏感节点人工审核。第一版先用“线上网站 + 本地受控采集”验证需求和流程，再评估是否升级为云手机/云真机采集。
