# 流程库改造：吸收 golden-flow-radar 经验

> 来源参考：`/Users/owinliu/.openclaw/workspace/radar/golden-flow-radar`
> 目标：把 `competitor-screenshot-hub` 的流程库从“截图聚合列表”升级为“黄金流程证据链”。

## 关键经验

`golden-flow-radar` 的核心不是展示截图，而是固定交付顺序：

1. 先确认事实节点。
2. 再整理文字版黄金流程。
3. 再生成流程证据图。
4. 最后补页面转译 / 界面流程分析。

因此流程库页面不应该只展示缩略图，而应围绕“节点是否可证据化”组织。

## 三个固定产出物

每条流程完成采集后，应至少沉淀三类产出：

1. 黄金流程文字版
   - 一句话概览
   - 主流程路径
   - 节点明细表
   - 分支与失败校验
   - 当前终点
   - AI 自动化 / 人工配合拆分
   - 待补采清单

2. 流程证据图
   - 截图 + 节点说明分离
   - 箭头标签必须说明点击动作
   - 失败/校验分支不能打断主流程
   - 缺截图节点用“待补采”占位

3. 页面转译描述 / 界面流程分析
   - 流程拓扑与页面数
   - 逐页面描述：整体风格、顶部导航、核心布局、文本与组件、底部区域
   - 只基于截图可见事实，不把口述节点写成截图证据

## hub 流程库需要呈现的字段

每个流程卡片至少展示：

- APP / 流程名
- 证据截图数
- 节点总数
- 待补采 / 待分类 / 人工接管节点数
- 当前终点
- 三件套产出状态：文字版 / 证据图 / 页面转译
- 节点证据链：序号、节点名、状态、证据图、备注

## 状态定义

- `captured`：有截图证据，可作为事实节点
- `needs-review`：有素材但分类/敏感/节点含义待复核
- `pending-capture`：流程上存在，但缺截图
- `human-required`：必须人工配合或接管
- `blocked-risk`：高风险节点暂停
- `oral-confirmed`：用户口述确认但缺截图，不能作为截图证据
